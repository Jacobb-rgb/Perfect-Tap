### 1. Ore luck on the mine floors (HIGH, fixed)
Floor rocks roll their ores from `MineFloors` (`floor.Ores`, or `floor.CrystalOres` for Crystal / Golden /
Geode / Giant rocks), but `dropChunk` let luck upgrade the ore inside `rock.Zone.Ores` (the WorldLayout map
weights). `BoostConfig.upgradeOre` keeps any ore that isn't in the table it gets.
- Floors 4-6 (Sunken Palace, Stormglass Rift, Heartstone Core) have `Zone.Ores = {}`: Hexa Lucky (a Robux and
  coin item), the Lucky / Starbreaker enchants and Luck golems did nothing there.
- Floors 1-3: luck upgraded into ores of the *map* table (e.g. Bronze / Gold out of a floor 1 Coal) that the
  floor's rocks never hold, and never touched crystal-rock ores (Emberite).
- The Hexa Lucky odds card, the luck cards (`BoostConfig.zoneEffects`) and `hasEffect` read the same map
  weights, so the odds shown for a paid odds-changing item were not the real odds (COMPLIANCE.md "show odds").
Repro (before): blaster LV 7, Hexa Lucky on, mine 50 rocks on floor 4: the drops are the same as without it.
Fix: each rock remembers the table it rolled from (`Rock.Weights`) and luck upgrades within it.
`BoostConfig.zoneWeights(zone)` / `crystalWeights(zone)` give the real tables (a mine floor's, else the zone's);
the odds card, the luck cards and `hasEffect` use them, and the Hexa odds list adds the crystal-rock ores as
"(crystal rock)" rows. Tests: tests/Step67Config.spec.luau, tests/BoostService.spec.luau.
**Behaviour change to know:** floor 1's rocks hold only Common / Uncommon ores, so Hexa Lucky now honestly
says it changes nothing there (coin buys answer NoEffect at blaster LV 1-2, as for any zone without Rare+);
from blaster LV 3 (Ember Caves: Bronze, Silver) it works. Within a floor whose ores all share one rarity
(Rift normal rocks: all Legendary; Heartstone Core: all Mythic) luck can't move anything either — that is the
floor design, not a bug, but the owner may want a Rare+ "jackpot" ore in floor 1 so a new player's Hexa does
something.

### 2. ELEVATOR jump on floors 2 and 3 (MEDIUM, fixed)
`TeleportService.groundAt` cast down from 40 studs above the target. Above floor 2's elevator stop that is
inside the ForgeMountain massif (the ray lands on the cave roof at world y 22); above floor 3's it is above
the ceiling slab (lands on the overworld grass). Repro: walk into Ember Caves, side menu → ELEVATOR.
Fix: the "Elevator" destination casts from `TeleportService.IndoorLift` (6 studs) above the plate.
Test: tests/Teleport.spec.luau. Still check in Studio (list below, item 1).

### 3. Gamepad stuck in the light HUD menu (MEDIUM, fixed)
With the light UI (shipped default) D-pad Left put the selection on the first HUD tile, but `inMenu` only
knew the hidden dark column: B was never bound, a second D-pad Left passed, and the MORE flyout never closed.
The left stick then moved through the tiles and the character could not walk. Fix: the light tiles and the
MORE flyout count as the menu (B leaves, D-pad Left from the left column leaves, leaving closes MORE), and
D-pad Left no longer selects a tile while the HUD is hidden (cleaning, Foundry moment).

### 4. Pass bought during a slow load (LOW, fixed)
`onPassPurchaseFinished` marks the pass bought but has no save to grant into while the load waits (up to 40 s
on a rejoin); the load's check then skipped it because it was "bought now". Fix: an "owned" answer is applied
even for a pass bought this session (only a "not owned" waits for the next load); it is still not counted as
owned-at-join, so Night Shift never tops up the offline payout for a pass bought this session.
Test: tests/MonetizationService.spec.luau.
