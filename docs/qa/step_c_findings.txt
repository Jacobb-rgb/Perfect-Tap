--- [high] timing-check-only-covers-cuts: Server timing check ignores scrape and polish timestamps, so a bot gets Flawless 3 s after CleanBegin
FILE /home/user/Perfect-Tap/src/server/Services/CleaningService.luau:201
PROBLEM The comment says every cut, scrape and polish timestamp must fit in the real session time. The code only adds up the cut durations (`latest += samples[#samples] - samples[3]`) and compares that sum to elapsed + 3. Scrape and polish timestamps are never compared to the server's elapsed time, and the only floor is GameConfig.CleaningMinSeconds = 3 (GameConfig.luau:34). The client records every timestamp relative to the session start (CleaningController.luau:170-171, ctx.now()), so the claimed timeline is easy to compare with the real one. Right now it is not compared. Timing is the only server-side defence against made-up input, because re-scoring cannot tell a perfect synthetic trace from a perfect human.
SCENARIO I tested this in Lune (scratchpad/qa/bot.luau), copying the server checks from lines 195-210. An exploiter hooks FireServer and builds a perfect payload: exactly on the line at 0.9 x MaxCutSpeed, all dirt removed, Fragile left empty, polish at 4.5 rad/s. The payload claims a 12.8 s timeline on Heartstone (Mythic). It is sent 3.0 s after CleanBegin and the server accepts it: 'OK Flawless score=1.000'. The same happens on all 10 ores. A real player needs at least about 13 s plus the step and crack animations, so the bot cleans about 4x faster than humanly possible and always gets the 2.4x grade.
FIX Because the timestamps are session-relative, check the whole timeline. (1) Find maxT, the largest t across all cuts, scrape and polish, and reject if maxT > elapsed + 2. (2) Require the steps to be in order: each cut's first t >= the previous cut's last t, the first scrape t >= the last cut t, and the first polish t >= the last scrape t. (3) Raise CleaningMinSeconds or make it per rarity (for example the sum of the minimum legit durations: cuts at MaxCutSpeed, polish at PolishBand.Max). After this, a bot has to wait as long as a human would.
