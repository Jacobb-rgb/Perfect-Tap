## What this is
TERRA FORGE is an original Roblox mining/crafting game in Luau, built with Rojo. The goal is a
**published, public Roblox game**. Loop: mine ore nodes → physical ore chunks drop → carry/throw
them → clean them in the signature **Cleaning Station minigame** (spray-wash the dirt off → reveal,
grades Rough/Clean/Pristine/Flawless) → crush/smelt/forge on machines
placed on your own plot (conveyors, build mode) → sell → upgrade.
Inspirations (feel only, nothing copied): The Forge (stylized low-poly, forge warmth), Hydroneer
(physical chunks, placeable machines, conveyors), Fishing Chef (step-by-step tactile minigame).
Lore, ores, names, UI and art are all original (docs/GAME_DESIGN.md).

## Layout (Rojo, default.project.json)
| Folder | In Roblox | What |
|---|---|---|
| src/shared | ReplicatedStorage.Shared | Config/* (all balance numbers), Builders/*, Cleaning/*, Machines/* (pure logic), Net.luau |
| src/server | ServerScriptService.Server | init.server.luau (ORDER list), Services/*, Data/* (ProfileStore, DataTemplate, Migrations), World/* (generated map, Lobby/*) |
| src/client | StarterPlayerScripts.Client | init.client.luau (ORDER list), Controllers/*, Cleaning/*, UI/*, Effects/* |
| src/first | ReplicatedFirst | loading screen |
| tests | – | Lune specs (tests/*.spec.luau), run by tools/lune/test.luau |
| tools | – | check.sh, build.sh, lune/ (loader, bake, export_scene), preview/ (three.js renderer) |

Services and controllers are ModuleScripts with `init()` then `start()`; the ORDER lists in the two init scripts
skip modules that don't exist yet with a warning.

## Rules that keep the code working
- Server-authoritative. Clients send intents through `Net` (src/shared/Net.luau: every client→server event has a
  token-bucket rate limit, handlers are pcall'd). Validate everything (src/server/Guard.luau).
- Strict Luau types everywhere (luau-lsp strict mode must say "no problems found").
- **Never start a Luau line with `(`** (ambiguous syntax error). Use a local variable.
- Every data change → `DataService.changed(player)`. New save fields go in Data/DataTemplate.luau; old saves are
  reconciled, structural changes go through Data/Migrations.luau (save Version = 6 since the one Furnace; the gate in DataService refuses saves from a newer build, see docs/SAVE_AUDIT.md).
- Mobile first: StreamingEnabled is on, keep part counts low, pooled particles, no per-frame server loops over parts.
- Roblox rules: TextService filtering for player text (forge name, 1-minute rate limit), no rewards for likes/favorites,
  ProcessReceipt grants only on the server that holds the session lock and saves first, show odds for any random reward.
  Full list: docs/COMPLIANCE.md.
- Kenney models are NOT imported as meshes (Roblox needs uploads under the owner's account). Rebuild their look from parts.

## Commands
```bash
rokit install                 # once: rojo 7.4.4, lune 0.8.9, luau-lsp 1.53.0, stylua 0.20.0 (rokit.toml)
bash tools/check.sh           # strict type analysis + all Lune tests + place build/bake → must say ALL CHECKS PASSED
lune run tools/lune/test.luau # tests only
bash tools/build.sh           # rebuild + bake build/TerraForge.rbxl (commit it: it is the playable place file)
```
Preview renders (pictures for the owner, no Studio needed):
```bash
cd tools/preview && npm install && npx playwright install chromium && cd ../..   # once
lune run tools/lune/export_scene.luau world                  # or: cleaning Gold spray|reveal [phone] / gameplay / ...
node tools/preview/render.mjs world town_overview great_forge  # shots in tools/preview/shots.json → build/preview/shots/*.jpg
SHOTS_EXTRA=tools/preview/lobby_shots.json node tools/preview/render.mjs world lobby_hero
```
The map is generated by src/server/World/WorldBuilder.luau; bump `WorldBuilder.Version` when the map changes
(the baked place rebuilds the map if the version differs).

## How work was organised
Build order: a) world + lighting ✔ b) ore chunks + carrying ✔ c) cleaning minigame ✔ d) machines/build mode/conveyors
(partly done) e) economy/shop/upgrades f) tutorial, monetization, badges, analytics, PUBLISHING.md.
After every step: QA review (errors, exploits, DataStore safety, mobile) + "what to test in Studio" in docs/QA_REPORTS.md,
then a short Czech summary for the owner with pictures.
Subagents live in .claude/agents/ (game-designer, luau-dev, qa-tester, asset-manager). Big steps were done with
multi-agent workflows: plan in docs/plans/*.md with work packages that own separate files, parallel builders in git
worktrees, an integrator, then adversarial QA. Example scripts: docs/handoff/workflows/.
Commit after every step. Never commit build/preview or node_modules.
